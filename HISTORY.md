# Дневная история WB

Реализован локальный архив SQLite. Установка на рабочем сервере и фактический
объём загруженных данных проверяются по разделу «История» в панели сравнения;
публикация кода сама по себе не подтверждает импорт.

## Первая загрузка и управление

Первое обращение к новому приёмнику ставит одно задание: с 01.05.2025 до вчерашнего
дня по Москве. Эта дата явно выбрана владельцем магазина. Сборщик обходит каждый
день для артикулов из таблицы, максимум 300. Он не обнаруживает весь каталог WB.
Старые версии сборщика не получают задания истории.

Загрузка идёт небольшими частями. После каждого дня сохраняются данные и курсор.
После перерыва продолжение начинается с сохранённой даты. Выбранное пользователем
сравнение получает приоритет между днями. Обычное ежедневное обновление сохраняется.
Лимиты WB дают паузу с учётом Retry-After; недоступные даты отмечаются отдельно.
Пустой ответ не доказывает нулевые продажи. Пропуски не заменяются нулями.

В панели доступны состояние, пауза, продолжение и запуск за выбранные даты.
Повторный обход обновляет существующие записи, не дублирует дневные показатели.
Фоновая история не переписывает ABC или текущие показатели таблицы.

## Что сохраняется

Файл: `/home/reportdeploy/wb-automation/history/history.sqlite3`, права 600,
каталог 700. SQLite входит в Python; дополнительных сервисов БД нет.

- `products`: магазин (хеш идентификатора), артикул, название, тип, время наблюдения.
- `daily_funnel`: показы, переходы, корзины, заказы, выкупы, выручка и доступные
  проценты WB. Ключ: магазин + артикул + день. Неизвестные значения — NULL.
- `daily_coverage`: полный, неполный, отсутствующий или недоступный ответ.
- `period_reports`: отдельные снимки многодневных и незавершённых периодов.
  Они не разбиваются искусственно на дни и не смешиваются с дневными суммами.
- `collection_runs`: аудит выполненных загрузок.
- `cost_observations`: изменения себестоимости, замеченные в таблице **сейчас**.
  Текущая цена не считается себестоимостью прошлого года. Исторические рекламные
  расходы и цены с датой действия этим изменением не восстанавливаются.
- `history_meta`: активный магазин, время обновления и локального резервирования.

При выборе «из истории» сравнение использует только товары с полным покрытием
каждого дня выбранного периода. Конверсии считаются из сумм дневных счётчиков;
они могут отличаться от собственных когортных процентов WB за большой период.
Источник WB по умолчанию сохранён. Себестоимость и реклама не влияют на ABC.

## Резервирование и восстановление

SQLite backup API создаёт согласованные копии в `history/backups/`, до семи
дневных файлов `history-YYYY-MM-DD.sqlite3`. Копия текущего дня обновляется после
части импорта. Файлы закрыты правами 600. Это копии на том же диске, не защита
от потери сервера; внешнее резервирование пока не настроено.

При восстановлении сначала остановить оба сборщика и таймеры. Сохранить текущий
каталог истории целиком. Копировать выбранный backup вместо history.sqlite3,
убрать оставшиеся WAL/SHM только после остановки всех подключений и сохранения
каталога, вернуть владельца reportdeploy и права 600. Проверить PRAGMA integrity_check
и затем возобновить сбор. Курсор Apps Script может быть новее восстановленной базы:
нужен повторный импорт недостающих дат через панель.

Обновление и откат программного кода не удаляют базу. Секреты, профиль Firefox,
содержимое архива и цены не публикуются в GitHub. Для 50 тысяч товаров текущую
очередь, каталог и ограничения API потребуется отдельно переработать.
