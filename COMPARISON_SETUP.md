# Обновление сравнения товаров

Для постоянной автоматической доставки следующих версий предпочтительна
однократная установка из [AUTO_UPDATE_SETUP.md](AUTO_UPDATE_SETUP.md).
Ниже сохранён способ разовой ручной установки.

Код в GitHub и код развёрнутого веб-приложения Apps Script обновляются отдельно.
Факт публикации в GitHub не означает, что панель уже появилась в таблице.

## Один раз в Apps Script

1. Открыть таблицу → **Расширения → Apps Script**.
2. Заменить содержимое существующего **CostReceiver.gs** готовым файлом из корня
   репозитория и сохранить. Это один файл: панель и её функции уже включены.
   Старую функцию `doPost` в другом файле не дублировать.
3. **Развернуть → Управление развертываниями → изменить существующее →
   Новая версия → Развернуть**. Существующие URL и свойства скрипта сохранить.
4. В списке функций выбрать **wbInstallComparison**, выполнить один раз и
   предоставить разрешения. Функции `doPost` и `wbInstall` запускать не нужно.
5. Установка добавит меню **Сравнение WB**, откроет правую панель и оформит
   существующие столбцы. Данные, формулы и справочник себестоимости сохраняются.

## Один раз на сервере

Закрыть Firefox, затем запустить от root `server/update-comparison.sh`, передав
SHA опубликованного коммита. Установщик использует имеющиеся `.env`, профиль,
виртуальное окружение и ежедневный таймер; повторно вводить секрет не нужно.
Он добавит отдельный таймер `wb-comparison.timer` в режиме ожидания команды. Сервер должен
иметь доступ к GitHub, кабинету WB и существующему Apps Script URL.

Ежедневный сбор и сравнение используют общий файловый замок, поэтому не запускают
две копии Firefox с одним профилем. После отмены старый результат не может
перезаписать новое задание. После трёх аварийных прерываний задание получает ошибку.

## Работа

- Открыть **Сравнение WB → Открыть панель сравнения**.
- Выбрать 2–300 артикулов через поиск по номеру, названию или типу товара.
  В существующем столбце V также сохраняются флажки выбора.
- Указать даты. Для режима с начала работы магазина один раз указать фактическую
  дату начала: автоматически она не определена. Можно запросить прошлый год,
  но доступность истории зависит от WB. Отказ не подменяется другим периодом.
- ABC использует только CTR, переход → корзина, корзина → заказ и заказ → выкуп.
  У каждого показателя одинаковый вес после нормирования к среднему выбранных
  карточек. Индекс со средним 100 не является вероятностью покупки или A/B-тестом.
  Финансы и число показов сами по себе не добавляют баллов.
- W — категория A/B/C, X — относительное отклонение индекса от среднего.
  Верхняя/нижняя треть распределения задаёт A/C, середина — B; равные значения
  получают одинаковые категории. При одинаковых результатах у всех — B и 0%.
  Если полных сопоставимых карточек меньше двух, оценки не присваиваются.
- Для ABC нужна полная воронка с положительными знаменателями. Отсутствующие
  показатели не превращаются в нули: показывается «Нет данных».
- Нажать **Сравнить**. Кнопка ставит задание на сервер; панель показывает состояние
  и результат. Без установленного серверного таймера задание останется в ожидании.
- Менять фильтр A/B/C после готового сравнения можно без
  повторной загрузки WB. Цвета относительные среди выбранных товаров.

Песочный фон M/N — ручной ввод; голубой A:L и O:U — загрузка и расчёты;
мятный V — выбор товаров. W/X показывают категории и отклонения по конверсиям.
Справочник себестоимости переносится целиком правее Z (обычно AA:AC); код находит
его по заголовкам, новые занятые ячейки не перезаписываются. Старый выбор периода
из W2 убран: период сравнения задаётся в панели. Существующие светофоры сохраняются и могут перекрывать
голубой фон у результативных показателей.

Сравнение относится к общей воронке карточек. Отдельная оценка рекламных кампаний
не реализована: для неё нужны рекламные показы, клики, расходы и атрибутированные
заказы. Прибыль в этой версии = выручка выкупов − себестоимость выкупленных единиц
− подтверждённые рекламные расходы. Комиссия, логистика и налоги не вычитаются.

Сравнение загружает данные только в существующие строки прогноза. Новые артикулы
не создаются. Другая вкладка не получает исторический период сравнения; её обычная
ежедневная загрузка продолжается. Недостающие в ответе товары не ранжируются,
прежние ячейки для них сохраняются, а список показывается в панели.
